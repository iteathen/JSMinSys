# C15: E-core asynchronous shared-exact publication

Status: frozen design warrant, implementation/qualification pending. Owner explicitly authorizes E-core asynchronous hot-work offload. Refreshed retained-kernel profile attributes about11.1% early-search self samples to shared exact stores (diagnostic, not full-cost guarantee).

Only move optional shared proof publication. Search keeps its private exact/bound cache, immediate shared lookup, child construction, pruning, order and exact root semantics. Four search workers stay pinned on P-core processors0,2,4,6. One helper binds to verified E-core processor12, group0 (core6, efficiency0,2MiB L2 from live query). Existing P-core validator must not be weakened; helper gets separate cold validation. Initialization creates helper and queues before the empty-board timer starts.

Prepare one bounded SPSC queue per producer:65536 records,32 records/publication batch. A record holds known hash, exact value, and the exact stored key (8 words on existing7x6 compact profile; general key width otherwise). All storage at initialization; never enqueue pointers to reusable recursion frames. Producer acquires consumed sequence only at batch reservation, writes payload normally, release-publishes complete batch with one atomic store. If full, skip optional sharing without blocking search. No node timers, allocations or reporting counters. Partial final batches need not be published for correctness.

Helper round-robin drains at most one batch per queue per pass. It alone writes shared TT in active mode, preserving existing full exact-key comparison and odd/even sequence protocol; readers stay unchanged. Single-writer publication can omit writer CAS, but retain atomic payload/value writes initially to avoid changing the reader protocol. No dedup or layout redesign in this candidate. If all queues idle, wait at most1ms on stop control rather than busy-spin; no producer wake/notify bookkeeping. Consume/release sequences prevent overwritten queue payload reads; use uint32 modular differences and explicit wrap tests.

No helper outcome/proof computation, no guessed entries, no persisted data, no search results imported. Only already proven exact1/2/3 codes enter queues. Private lower/upper bounds remain private. Concurrent publication failures/delays are cache misses, never licenses for approximate results. Stop/error/cleanup must include helper; report4 search+1 maintenance, total5 exits. Queue producer/consumer indices may be inspected only after completion; no added hot reporting counts.

Controls: A retained original process mask85/direct stores/no helper; B mask4181 (85|1<<12), initialized idle helper with same queues, direct stores; C identical B placement/memory but asynchronous publication. B separates expanded process affinity/V8 background scheduling and helper lifecycle from publication effect. Compare C vsB causally and C vsA for retention. No silent E-core fallback. Record actual helper affinity and total-process CPU/cycles/RSS. Do not change shared/private TT entries or retained JIT flags in this experiment.

Validation: queue boundaries/full drop/partial batch/wraparound; immutable key snapshot after source-frame mutation; exact compact and generic key transport; reader-visible odd/even protocol under collisions and concurrent producers; no4/5 bound publication; four-search-worker independent post-return physical minimax roots with5 total clean exits; prepared empty readiness and cancellation/error teardown. Generated worker/source identities and NEES ledger maintained. Then repeat complete localhost empty solves under A/B/C; no performance conclusion from a timed-out/incomplete run.

Failure does not reject all E-core work. Later independent candidates could deduplicate redundant publication on helper or precompute geometry plans, but those must not be bundled into the first trial.
