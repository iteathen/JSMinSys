Qualification outcome is recorded in the linked evidence report when complete.

## Execution contract

- E0: `searchCpcOnlyFrontier`, completed-node flag reader and CPC closure.
- E1: native cofactor, reflection, live-line scoring, full-key exact TT access.
- E2: retained root-action obligations, repeated bounded passes and deep release.
- E3/COLD: ingress, prepared geometry/storage/Wasm reader, worker construction,
  result objects, reporting, FFI cycle measurement and terminate/join.
- Semantic owner: `rba-connect4-frontier.mjs`, generated by
  `tools/build-root-frontier.mjs` from the ordinary behavior solver; the generator
  owns the distinct full-window root loop. No runtime rewriting or experiment
  import exists in the selected execution path.
- Governing performance unit: whole seven-worker solve including initialization,
  startup/JIT, useful and redundant work, sharing, result closure and cleanup.
  Single-worker/node measurements are diagnostic, not the acceptance objective.
- Regression surface: ordinary/optional workers, configurable geometry,
  reflection/witness, forced chains, incomplete horizons, cancellation/reuse,
  node accounting, shared exact publication and cold-start economics.

The hardware profile is Windows x64, Intel i5-12600K (hybrid 10-core/16-thread),
Node 26.7.0 / V8 14.6.202.34-node.28. Seven workers use 4,194,304 shared entries
and 1,048,576 private entries each, full exact sharing, unchanged move order.
Worker 0 starts at horizon 2 and increases by 2; when at most one unresolved
root action remains it releases to deep search. Peers start released. This
counts root obligations, not every frontier leaf, and is not adaptive PFIF.

An unresolved horizon returns numeric sentinel 4, never WDL. Recursive parents
propagate it without exact publication; a witnessed sound cutoff remains usable.
STOP is sentinel 3. Root action values survive between passes. RBA cofactor and
canonicalization own children; no board/history reconstruction occurs per node.
Root live-line initialization is cold and occurs once per prepared solve.

Root words, residual coordinates and bases occupy preallocated per-depth spans;
scalar parent values survive child calls. Geometry and profile are fixed during
search. TT collision is an exact-key miss/overwrite, never identity equivalence.
Only complete exact WDL enters shared TT. Capacity does not grow during search.
First-win, support, player polarity, reflection and action labels are preserved.

## Ownership and behavior

The host prepares one shared behavior memory and publishes one command per
worker before spawning. The selected profile has no strategist. The numeric
reader still observes its own flags at every completed node, including the
extension-publication protocol. Only STOP/stride/release/target have meanings in
this profile. Deleted campaign bits cannot alter move ordering, CPC or TT policy.

Unchanged word: prepared atomic load, extension test, equality test, return.
Changed word: decode numeric frontier fields; no current frame or exact evidence
is rewritten. Each new solve resets the private last-observed word before entry
so the initial command is reapplied after an earlier automatic release.

Shared TT uses its existing committed-row protocol. Worker metrics/node counters
are single-writer, partitioned shared storage. Authoritative counter reads happen
after every worker has joined. There is no concurrent reader relying on an
ordinary Float64 write being atomic. Counters never control game semantics.
The per-worker node slot replaces the prior increment; it is not a second count.
No synchronous coordinator or message is needed to advance a node. Threads are
created per solve and closed on all terminal paths; reusable-pool economics remain
explicit debt for repeated tiny tasks, not hidden preparation savings.

## Cost and realization record

`catalog/addon-cycle-ledger-v0.json` includes all new function/module units and
resolves the selected worker's transitive call graph, including prepared profile
callbacks. The complete-node reader has an executed common/change/extension-path
ledger. Recursive horizon/sentinel/counter deltas and root repeated-pass work
are explicit. No local operation is priced as zero because it is unmeasured.

The legacy numeric table is a **Zen 3 reference**, not an Alder Lake estimate.
On this hardware, retain its operation inventory but bind realization costs to
symbolic memory, branch, field, JIT and boundary terms. ROOT_CONTROL-style dynamic
counts are source-level models; exact instruction counts are not claimed.
The measured cost profile is Windows QueryProcessCycleTime, all process threads,
user+kernel cycles, partitioned into bootstrap/setup/whole solve. Dividing by
aggregate worker nodes is descriptive, not a predicted cost of one node.
Wall time remains the time-to-solution objective. No nominal-GHz conversion.

FFI record (COLD only): kernel32 GetCurrentProcess() -> borrowed pseudo HANDLE;
QueryProcessCycleTime(HANDLE, borrowed 8-byte output buffer) -> BOOL/int32;
GetLastError() -> uint32 on failure. Windows x64 ABI, Node experimental FFI
enabled explicitly, no callback or owned handle to free; the library stays open
through reads and closes in finally. Buffer lifetime covers each call. Wrong ABI
can crash/corrupt the process; unsupported OS fails instead of inventing cycles.
No Fast-FFI or exact CPU retirement-count claim is made.

### Scoped JSMinSys deviations and inherited realizations

1. **Prepared Wasm atomic reader**: retain the existing deviation in
   `worker-behavior.md`. The sole operation is i32.atomic.load from a cold-bound
   address. Compilation/100k warmup, JS/Wasm guards/call/return and extension
   logic are counted. Every-node observation is required; initialization-only
   sampling is not an alternative. No new foreign game logic is admitted.
2. **Prepared object handles/field access**: the add-on scope uses cold-created
   geometry/state/cache/profile objects with stable fields and bounded callbacks;
   no object is created per node. This supplements the narrower JSMinSys core
   vocabulary, not global admission of arbitrary object graphs. Flattening all
   handles is UNVERIFIED-DEBT until whole-solve evidence supports it. Field loads,
   stores, call/return, boxing/deopt risk and retained storage remain costed.
3. **Typed fill and Float64 diagnostics**: existing bounded scratch resets use
   TypedArray.fill; node totals use a prepared Float64 slot, exact only through
   Number.MAX_SAFE_INTEGER. These are scoped add-on operations, not uint32 game
   identity. The selected bounded runs are well below this range. Counter overflow
   affects measurement validity, not WDL. Cold reporting checks safe-integer totals.

Review owner: this repository's maintained implementation review. Revisit all
three records on Node/V8/CPU/profile change, new flag action/callback, an altered
storage lifetime, observed hot allocation/deopt regression or conflicting
whole-solve evidence. JSMinSys level: **JMS-RESTRICTED with these deviations**;
the lexical/call-graph structural detector is not a complete JS parser or proof
of all V8 internals, so **JMS-SEALED is not claimed**.

Mechanisms changed: ALLOCATION-LIFETIME/REPRESENTATION (unused cold tables and
fields removed), JIT-ENGINE (smaller fixed dispatch), DIAGNOSTIC (direct prepared
node slot, no rewriting) and DERIVATION (build-time generation). The expected
benefit is removal of campaign-only startup and action decoding. Falsifiers:
changed WDL/move/work on deterministic controls, invalid partial publication,
missed completed-node read, worse matched whole-solve cost, or new hot escape.
These falsifiers govern retention; a smaller source tree alone is not a win.
